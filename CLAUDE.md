# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

Set up as in CONTRIBUTING.md (Python 3.11+, pip 25.1+ for dependency groups):

```sh
python -m venv .venv && . .venv/bin/activate
python -m pip install --group dev -e .
```

```sh
python -m pytest                                    # full suite, ~2 min (ReDoS + Hypothesis fuzz dominate)
python -m pytest tests/test_refang.py -k defang     # one file / one test
HYPOTHESIS_PROFILE=fuzz python -m pytest tests/test_fuzz.py   # 20,000 examples instead of 200
ruff check src tests scripts
ruff format --check src tests scripts
mypy --platform linux                               # strict, src/ttprism only; matches CI, which type-checks on Linux
ttprism validate-rules                              # after touching rules/attack/
```

CI (`.github/workflows/ci.yml`) runs lint, mypy and rule validation on Linux / Python 3.13, tests on
Linux 3.11–3.14 plus Windows and macOS 3.13, and installs the built wheel outside the tree to check the
bundled rules load.

Some tests skip locally unless optional tools exist: `test_pdf_soft_hyphens.py` and
`test_research_pipeline.py` / `test_research_truth.py` need pypdf, cryptography, iocextract, ioc-finder,
pdftoppm, Chromium and git (versions in `docs/research/2026-10-real-reports/requirements.txt`).

## Architecture

`src/ttprism/analyze.py` is the pipeline; everything else feeds it:

- **Input** (`inputs.py`): read bytes with a size cap (`--max-size`, default 64m), decode, bounded JSON
  nesting. `analyze_file` auto-detects CAPE (`cape.looks_like_cape`) for input starting with `{`, else
  falls back to text with a warning.
- **Text path** (`analyze_text`): `refang.refang()` first normalises defanged / full-width / CJK-bracket
  forms and PDF line-wrap artefacts into plain text, then `extract.extract_into()` runs the IOC regexes,
  and `find_technique_ids` collects ATT&CK IDs the author wrote. TTPrism never infers techniques from
  prose. If the text contains U+00AD, the text is extracted a second time with soft hyphens deleted to
  warn when the two readings disagree.
- **CAPE path** (`analyze_cape`): `cape.parse_cape` reads only known, type-checked fields into IOCs plus a
  behaviour record (commands, APIs, registry writes, signatures); signature TTP labels become `reported`
  techniques and `RuleSet.evaluate` (in `attack.py`) matches YAML rules against the behaviour.
- **ATT&CK** (`attack.py`): `AttackCatalog` is `src/ttprism/data/attack_enterprise.json` (generated by
  `scripts/update_attack_catalog.py`) and resolves revoked/deprecated IDs into `original_ids`.
  `TechniqueAccumulator` merges reported and rule hits. The command matcher is indexed for speed;
  `tests/reference_matcher.py` is a frozen copy of the pre-index matcher and
  `tests/test_attack_equivalence.py` proves both agree. Change the reference only when command-phrase
  semantics change on purpose, never to follow a refactor.
- **Filtering** (`analyze._filter`, `allowlist.py`, `extract.is_reserved_*`): reserved values, the
  allowlist (`src/ttprism/data/allowlist.yaml`) and heuristic drops. Every drop increments a named counter
  that ends up in `AnalysisResult.suppressed`; new filters must count, not silently discard.
- **Output**: `export.py` (JSON, CSV with spreadsheet-formula escaping, optional `defang`), `stix.py`
  (STIX 2.1 bundle). `cli.py` wires `extract` and `validate-rules`.

Rules live in `rules/attack/*.yaml` at the repo root but ship inside the wheel as `ttprism/rules/attack`
(hatch `force-include`); `attack.default_rules_path()` tries the packaged path first, then the source
tree. The rule format and the command-normalisation steps are documented in `rules/attack/README.md`.

`docs/research/` holds the evaluation against other extractors and real reports (`evaluate.py`), with
its own tests (`tests/test_research_*.py`). Its JSON files contain real malicious IOCs from public
reports. Reading them is fine; never visit, resolve or fetch any indicator in them, and do not edit the
results files: the research note cites them and specific commit hashes. Raw evaluation inputs go in the
git-ignored `eval-data/`.

## Constraints that shape changes

- **All input is attacker-controlled.** Every regex must run in linear time on Python's backtracking
  engine: start with a negative lookbehind so matches begin only at a token boundary, bound every
  repetition, avoid overlapping adjacent quantifiers. Add a pathological ~1 MB case to
  `tests/test_redos.py` for any new pattern (limits are seconds per MB, see `tests/timing.py`). Nothing
  is executed, fetched or decompressed.
- New IOC forms need a positive and a negative test.
- Runtime dependencies are only PyYAML, deliberately; ask before adding one; YAML from users goes
  through `_yaml.py`'s safe loader.
- `tests/test_repo_hygiene.py` rejects invisible and bidi characters in tracked text files; write such
  characters as escapes (for example `\u00ad` for a soft hyphen), not literally.
- Test data must use reserved values only: `example.com`, `.example` / `.test`, documentation IP ranges
  (`192.0.2.0/24`, `198.51.100.0/24`, `203.0.113.0/24`, `2001:db8::/32`), hashes of harmless strings.
  Only TLP:CLEAR material, no malware.
- The README's Limitations and Filtering sections describe exact behaviour (line-wrap joining, soft
  hyphens, `suppressed` keys); keep them in sync when behaviour changes, and add user-visible changes to
  `CHANGELOG.md` under *Unreleased*.
- `README.zh-TW.md` mirrors `README.md` section for section, with the same commands and output. When
  behaviour, options or examples change, update both in the same change; the English README is the
  reference if they disagree. All links in both are absolute GitHub URLs, because `README.md` is also
  the PyPI page.
- Bundled data updates: `scripts/update_attack_catalog.py` (then bump `attack_version` in rule files after
  reviewing `validate-rules` warnings) and `scripts/update_tlds.py`.

## Workflow

- `main` is protected: work on a branch and open a pull request; all 8 CI checks must pass. Merge
  with "Create a merge commit", never squash or rebase, and never rewrite published history.
- Do not push, tag, merge, publish or change repository settings without the maintainer's explicit
  approval. Releases are tagged and signed by the maintainer (`docs/maintainer-setup.md`).
- Use the project's virtualenv; do not install interpreters or change the system environment.
- After editing any file, rerun the relevant checks (at least `python -m pytest tests/test_repo_hygiene.py`
  and the affected tests) before reporting the work as done.
- Never put vulnerability details in public issues, pull requests or commit messages; fix reported
  vulnerabilities through a private GitHub security advisory and follow the timeline in SECURITY.md.
- When reporting CI status, use the run for the latest commit; a run cancelled by a newer push counts
  as neither passed nor failed.
